## 发布准备

记录前端、Spring API、Flyway、JWT 密钥、Redis 刷新格式、Hocuspocus 网关、内部 HMAC、MinIO Y.Doc schema 与 feature flag 的兼容矩阵。确认所有可见 V2 项目均有团队归属和可加载的当前 `collab_document` 指针；旧匿名项目及 V1 revision/快照入口隔离。备份 MySQL 与 MinIO，确认恢复当前指针的操作说明。

生产入口同源暴露静态页面、`/api` 和精确 `/collaboration`；内部 API 不暴露公网。先停止旧写流量并 drain，执行全部增量迁移，部署从启动起强制 Bearer 认证且兼容迁移的新 API/网关/前端。在仅受控访问的入口完成功能检查后，再原子切换静态页面、`/api` 和 `/collaboration` 的外部路由，开放完整 V2。没有数据库认证切换状态，也不通过配置关闭 V2 认证。切换后只允许回滚到强制认证、兼容全部已执行迁移且拒绝旧匿名项目与 V1 快照/历史恢复链路的制品；若没有合格回滚制品，保持外部写入关闭或项目只读，直至修复。协作故障时可关闭协作入口并保持项目只读，直到当前对象指针对账完成。

## 最终功能流程

1. 用户 A、B 分别自助注册并登录。A 创建团队成为 OWNER；B 先申请加入并由 A 批准。另用用户 C 验证 A 按用户名或邮箱查找账号、确认身份后发送站内受邀，C 在“我的邀请”接受或拒绝；验证不存在的用户名和邮箱只显示提示且不产生邀请，仅目标账号能处理，过期/撤销/已处理邀请失效。审批或接受前不能访问团队项目。
2. A、B 均能创建项目，且两个角色对团队项目拥有相同的编辑、文件操作、复制、修改元数据和软删除权限；只有 A 能管理成员。
3. 新项目创建后立即存在持久化的初始 Y.Doc。两人编辑文本与文件树，看到 Presence/远端光标；HTML/CSS/JS 补全和诊断、JS checkJs 类型检查及 Sandpack Preview/Console 可用。
4. 编辑后自动 flush，界面分别显示同步与持久化状态；网关重启从当前 Y.Doc 指针加载文件。离线编辑、刷新后重新登录和重连可在重新授权后合并，同 epoch CAS 冲突不静默覆盖。
5. A 移除 B 后，B 的 REST、新票据和旧票据握手立即拒绝；确认撤权控制事件送达后，现有连接关闭，离线队列不能重新接入；其他成员继续编辑。
6. 有效成员软删除项目时先持久化并关闭房间，旧 epoch 和旧本地队列不能再次写入；对象保留但项目不再可访问。
7. 页面与 API 均无版本列表、检查点、历史恢复、版本比较或回退功能；不会创建新的 `project_revision`，旧 V1 revision 对 V2 用户不可见。

验收以这些功能流程可用、当前对象指针一致、旧匿名项目隔离和秘密不泄露为准；不要求专用本机 MySQL/MinIO/Redis 集成验证、双浏览器自动化、压测或故障演练报告。运行应用时使用仓库根 `.env` 的本机服务，不使用 Docker，不打印凭据。
