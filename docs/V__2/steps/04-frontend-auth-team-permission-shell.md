# 步骤 04：前端身份与团队界面

> 前置：步骤 03 的团队后端设计与实现。状态：未开始。登录壳先完成，公开切换由步骤 11 执行。

## 登录与团队流程

React Router 提供 `/register`、`/login`、团队发现、邀请接受、团队与项目路径。凭据只在页面内存；整页刷新后重新登录。受保护请求携带 `Authorization: Bearer`，固定 `credentials: omit`；401 清空内存身份，403 显示拒绝，429 按 `Retry-After` 提示。刷新凭据单飞轮换，不进入 URL、日志、浏览器持久层或 Sandpack iframe。

注册成功后显式登录。用户可创建团队、搜索允许申请的团队、提交或撤回申请、接受 fragment 邀请。加入申请未获批时不显示该团队的项目。邀请 token 由页面内存持有，登录/注册后提交，刷新页面时要求重新打开邀请链接。

团队成员列表对所有有效成员可见；仅 OWNER 显示邀请、审批、移除、加入策略和所有权转移操作。项目界面中 OWNER/MEMBER 的创建、编辑、文件操作、复制和删除入口完全相同，不显示项目角色、成员授权或 Viewer 模式。

## 项目界面切换

步骤 03/04 先完成登录与团队界面，但不向生产用户公开；项目创建依赖步骤 05 的初始 Y.Doc 原子创建，编辑器依赖步骤 07 的 Monaco/Yjs，整体入口在步骤 11 开放。不要让浏览器 `DEFAULT_FILES`、V1 快照上传或 revision 保存临时承担新项目初始化。V2 UI 不显示版本列表、版本恢复、检查点或版本比较。旧 V1 项目/版本页面与 API 在认证切换后不可达。

项目详情路由为 `/teams/:teamId/projects/:projectId`。缓存键至少包含 userId、teamId、projectId；退出登录、退出团队、被移除或 401 时取消在途请求并清理缓存。旧无主 IndexedDB 草稿不自动认领；步骤 08 将新草稿转换为按 userId/projectId/epoch 隔离的 Yjs 缓存。项目元数据更新与删除使用 `If-Match`；409 提示重载，不静默覆盖。

## 发布与验收

本步骤完成功能检查后保持新入口暗置。步骤 11 在停写窗口执行全部迁移、部署从启动起强制认证的完整 V2 服务与登录 UI，受控检查通过后切换外部入口。切换后回滚仍须强制认证，不恢复匿名 API、旧快照保存或历史版本入口。

功能验收确认自由注册、登录/刷新、创建团队、申请与邀请加入、OWNER 成员管理、非成员拒绝、旧匿名项目隔离；确认 V2 页面没有版本控制入口，项目创建仅在步骤 05 完成后开放。运行应用使用根 `.env` 的本机服务，禁止 Docker，不输出凭据；无需双浏览器自动化验收。
