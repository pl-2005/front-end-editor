# 步骤 03：团队成员授权、加入流程与旧项目隔离

> 前置：步骤 01、02。状态：未开始。步骤 03 完成团队后端；步骤 11 才公开切换强制认证与完整 V2。

## 授权

团队角色只有 `OWNER`、`MEMBER`。创建者是首位 OWNER；邀请和申请获批固定成为 MEMBER。OWNER 仅管理成员邀请、申请审批、移除、加入策略和所有权转移。团队恰有一位有效 OWNER；退出前须转移。任意有效成员可创建、读取、编辑、复制、修改元数据和软删除该团队项目。没有项目角色、项目成员表、可见性分级或只读成员。

`TeamAccessService` 校验用户存在、团队 ACTIVE、有效 `team_member` 和项目 `team_id`；成员管理额外校验 OWNER。列表在 SQL 层按团队成员关系过滤。不可见项目返回 404，已登录但无成员管理权限返回 403。成员加入、退出、被移除和 OWNER 转移递增受影响用户的 `authz_version`，服务端每次查询当前关系。退出/移除立即影响 REST 与新协作票据；步骤 09 负责关闭现有连接。

## 数据迁移与旧项目

V6 追加 `team`、`team_member`、`team_invitation`、`team_join_request`，并给 `project` 加可空 `team_id`、`created_by` 和 `legacy_unowned`。团队只有 OWNER/MEMBER，成员只有 ACTIVE/REMOVED；邀请与加入申请各有有限状态和过期/消费时间。邀请 token 只保存摘要。V7 约束新项目必须有团队和创建人，旧匿名项目才允许缺失。后续存储迁移按实际顺序追加，**不新增或回填 revision 元数据**。已发布 Flyway 文件不改写。

V1 项目没有可验证所有者。停写后将迁移前项目标记 `legacy_unowned=true`，保留原项目、revision 和 MinIO 对象；不认领、不分配、不导入。V2 列表、详情、文件、复制、删除、票据和内部网关入口全部排除旧匿名项目。新团队项目创建流程不写 `project_revision`；步骤 05 从服务端模板创建初始 Y.Doc。步骤 05 前可将新项目创建入口保持关闭，避免出现没有内容指针的项目；团队与成员功能可先完成。

步骤 03/04 只完成实现与功能检查，不提前公开不完整的 V2。V2 服务从启动起对项目 API 强制认证。步骤 11 在所有新项目、协作、删除和撤权功能就绪后执行全部迁移，部署完整 V2 制品并在受控检查通过后切换外部入口；旧匿名入口和旧 V1 版本/快照 API 不得重新开放。Flyway DDL 隐式提交，迁移失败按实际 schema 与 history 对账，不假定自动回滚。

## 加入与邀请

- 任何已登录用户可以创建团队并成为 OWNER；同一用户可属于多个团队。
- 团队加入策略为 `REQUEST`（默认）或 `INVITE_ONLY`。团队发现只显示允许申请加入团队的公开基本资料，不显示成员或项目。
- 未加入用户可申请或撤回申请；OWNER 批准或拒绝。批准事务复核团队 ACTIVE、策略允许、申请人存在且尚非成员，再创建 MEMBER。申请中没有团队资源权限。
- OWNER 可创建和撤销邀请。邀请链接使用 URL fragment，前端读取后清除地址；接受通过 POST body 提交，token 不进入日志、查询参数或浏览器持久层。接受时复核目标团队、过期状态和绑定邮箱，原子消费。无效/过期/已用/撤销统一返回 410。
- MEMBER 可自行退出；OWNER 须先转移。OWNER 可移除其他成员，但不能移除自己造成无 OWNER 团队。

## API 边界

| 接口组 | 授权 |
| --- | --- |
| 团队创建、发现、本人加入申请、接受邀请 | 已登录用户；发现允许匿名只读 |
| 团队及成员列表、团队项目列表/详情、项目创建/编辑/复制/删除 | 有效团队成员；项目操作 OWNER/MEMBER 同权 |
| 邀请、申请审批、成员移除、加入策略、所有权转移 | 团队 OWNER |
| 退出团队 | 本人有效成员；OWNER 须先转移 |
| V1 revision 列表、恢复、浏览器 snapshot 保存 | V2 关闭；不得作为新项目持久化入口 |

唯一新项目创建入口为 `POST /api/teams/{teamId}/projects`，由步骤 05 提供初始 Y.Doc 原子创建能力；旧 `POST /api/projects` 关闭。DTO 不接受客户端指定 OWNER、项目角色、创建人、状态或存储指针。项目元数据更新继续使用步骤 01 的 `If-Match`。

## 功能验收

确认自由注册后可建团队、申请和邀请加入；仅 OWNER 能管理成员，OWNER/MEMBER 对项目同权；申请中、非成员、退出成员和旧匿名项目均不能访问团队文件。确认旧 revision/快照 API 不对 V2 项目开放，新项目待步骤 05 完成后可直接获得 Y.Doc 指针。无需专用三服务集成验证或双浏览器验收；运行应用使用根 `.env` 和本机服务，禁止 Docker 与秘密输出。
