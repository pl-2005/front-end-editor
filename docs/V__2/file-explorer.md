# 项目文件管理交互

文件栏采用 Ant Design Tree，文件夹和文件共用右键及「…」菜单。

| 操作 | 使用方式 |
| --- | --- |
| 选择新建位置 | 选中文件夹；选中文件则使用其父目录。点击顶部「文件」回到根目录 |
| 新建文件／文件夹 | 顶部按钮或目录菜单，在树内输入名称；Enter 或「确认」提交，Esc 或「取消」放弃 |
| 上传文件 | 顶部「上传文件」按钮或文件夹菜单，可多选；上传到选中文件夹，选中文件时上传到其父目录，点击顶部「文件」可选择根目录 |
| 重命名 | F2 或菜单，在原位置编辑名称；整棵目录一次事务改名 |
| 移动 | 拖动到目标文件夹，或「移动到…」选择目录／根目录；保留文件 ID 和内容 |
| 删除 | Delete 或菜单；目录确认显示路径和文件数，最近一次删除在 15 秒内可撤销 |
| 折叠 | 顶部「折叠全部目录」；普通内容更新保留折叠状态 |

名称输入即时校验重名、特殊字符、路径长度和支持的扩展名（html、css、js、json、txt、md）。失败保留输入。成功的新建文件自动打开，目录改名／移动会保留展开状态。

入口文件及包含入口文件的目录不能删除；只读状态禁用所有修改操作。撤销先验证原路径和逻辑删除标记，拒绝覆盖新文件或其他修改。移动及重命名不会自动更新源码引用，会提示用户同步修改。

## 上传文件

支持 `.html`、`.css`、`.js`、`.json`、`.txt`、`.md`，文件须为 UTF-8 文本；拒绝非法 UTF-8 及包含 NUL 的二进制内容。支持空文件，保留实际正文和换行，不插入新建文件模板；解码时去除 UTF-8 BOM。当前不支持图片、ZIP 或文件夹批量导入。

单文件最多 1 MiB，项目最多 100 个文件、总正文最多 10 MiB；逻辑删除文件仍占用数量与正文容量。上传同样受 12 MiB Y.Doc、2 MiB Update 和 1.5 MiB 本地待确认日志预算约束，因此一批文件即使符合单文件和总正文限制，也可能需要减少数量或等待已有更新持久化后再上传。

上传时锁定目标目录，读取期间显示加载状态并禁用再次上传。全部文件读完后，再以当前协作文档校验权限、容量及路径；与现有文件／目录冲突、批次内重名、任意读取或校验失败时，整批不写入，不覆盖已有内容。成功后自动打开本批第一个文件，并显示上传数量。读取期间权限失效或离开工作区不会提交文件。

正文经 `readUploadFiles` 解码，再由 `fileCommands.importFiles` 在一次 Yjs transaction 中创建稳定 fileId 和 Y.Text；`CollaborationSession.mutate` 在临时文档中预检结构及更新预算后才提交。沿用 WebSocket 同步、IndexedDB 离线日志和 MinIO 当前文档持久化链路，不新增 REST 上传接口，也不让浏览器直连 MinIO。「已上传」表示文件已加入本地协作文档；服务端保存完成仍以工作区「已持久化」状态为准。多人同时上传相同路径时，沿用稳定 fileId 的冲突归一化规则。

## 目录与协作协议

schemaVersion=1 增加可选根映射 `directories: Y.Map<path, true>`，保存显式目录及空目录，上限为 100 个。旧文档没有该映射仍然有效。根映射避免两人首次同时创建目录时覆盖彼此的数据；目录按路径排序参与指纹，确保不同更新到达顺序不影响持久化确认。浏览器与网关共用目录校验，并沿用原有离线日志、对象持久化和项目复制。ZIP 导出包含空目录。删除或移走最后一个文件／子目录时保留原父目录。

目录操作先验证所有目标路径，再通过一次 Yjs transaction 更新子文件和目录。文件数及容量限制保持不变。首次使用新功能前，应将浏览器、网关和初始化服务一起更新并重启；旧服务的严格校验不接受新增目录字段。已有新目录数据的项目不能回滚到不支持该字段的版本。

## 验证

前端测试覆盖就地新建与重名提示、取消、快捷键、右键、拖动移动、目标选择、目录删除与撤销、只读限制；文档测试覆盖空目录同步、整体改名、冲突拒绝、入口保护、撤销拒绝覆盖、复制及导出。

上传自动化用例位于 `frontend/src/collaboration/uploadFiles.test.ts`、`document.test.ts` 和 `frontend/src/editor/v2/WorkspaceFileExplorer.test.tsx`，覆盖 UTF-8／BOM／空文件、非法编码及二进制拒绝、类型和容量限制、多选目录上传、冲突后重试、整批失败不写入、单事务同步和只读限制。2026-10-16 本次上传相关定向运行共 23 项通过，前端完整测试集 27 个文件、203 项通过，lint、TypeScript 与生产构建通过；下方既有本机服务脚本未在本次变更中重跑，不作为上传真实服务验收记录。

手工验收：按[开发指南](development.md)使用根 `.env` 启动本机服务，在测试团队项目选中一个文件夹，上传多个文本文件并核对正文、预览和另一成员工作区；等待「已持久化」后刷新确认文件存在。再验证同名文件、超限及错误编码文件上传失败且已有内容不变，并在协作不可编辑时确认上传入口禁用。

本地服务验收使用根 `.env` 的 MySQL、MinIO、Redis，在独立端口启动临时服务，仅操作新建测试项目并结束时软删除，不中断已有实例：

```powershell
Push-Location collaboration
node --env-file=../.env node_modules/typescript/bin/tsc
node --env-file=../.env scripts/verify-file-explorer-local.mjs
Pop-Location
```

验收需要已存在的 `.codex-build/step11-backend/backend-0.1.0-SNAPSHOT.jar`。使用端口 18598、18599、18600，并用 15575 作为测试 WebSocket Origin；进程退出前 flush 网关并关闭临时服务。运行日志位于 `.codex-build/file-explorer-local.log`，不提交配置、凭据或测试服务数据。
