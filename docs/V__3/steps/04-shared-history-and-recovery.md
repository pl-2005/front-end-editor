# 步骤 04：共享历史、结构冲突检测与本机恢复

日期：2026-10-12。状态：待实施；文档审查见[审查记录](../development-review.md)。阶段：P1 基础。前置：[03](03-atomic-patch-and-dependencies.md) 原子计划及 01 对检测、历史和崩溃顺序的证明。

## 目标与接入

在首个产品写入口开放前建立会话级 HistoryController 和 RecoveryStore。接入 `MonacoWorkspace.tsx`、`session.undo/mutate`、`OfflineLog`，仅保存本机派生元数据；不新增用户历史版本或共享页面树。首版存在远端贡献/引用时拒绝整组撤销，不实现未经验证的部分补偿。

## 实施任务

1. 会话统一创建/销毁 UndoManager，Monaco 快捷键、画布工具栏及后续按钮共用它。真实和 scratch 的 scope、trackedOrigins、capture/deletion 等影响结果的选项一致，保留既有 redone 元数据处理并验证其正确性；至少覆盖 files/fileOrder，目录/meta 被计划修改时同时覆盖，不默认追踪全部 STRUCTURE_ORIGIN。
2. 仅跟踪本地 MonacoBinding 与 VISUAL_ORIGIN；插入/删除/移动/复制及单次属性提交前后切断 capture，一次操作跨文件一组。连续属性输入以目标、字段、焦点、提交/取消为边界，代码输入不意外合组；多个 Monaco model 和设计文件切换使用同一会话操作顺序。
3. 为历史项保存受影响文件/目录、创建身份、本地贡献及后续事务/引用证据；undo 和 redo 在 scratch 与 live 前都做依赖检查。远端新增内容、vendor/许可修改、其他 HTML/CSS/JS 新引用及目录新依赖存在时，整组拒绝且保留正文、文件身份和栈顶；引用无法证明安全时保守拒绝并说明。不能用当前字符串等于初始内容证明没有远端贡献。
4. 正式实现 P0 已证明的冲突检测候选：观察相关本地/远端事务及后续合并，关联操作来源、目标、前后锚点与上下文，检测合法但重复/漏搬的结果。double-move、move-delete、move-late-text、嵌套父子移动和尚未收到贡献的 undo 均覆盖两种到达顺序。属性原值冲突在提交前拒绝；同点插入展示实际 CRDT 顺序并验证结构。不得仅凭重解析成功或 hash 一致判定无冲突。
5. OfflineLog 有界侧车记录 operationId、user/project/epoch、涉及文件、操作前文本、必要后文本/上下文、相对锚点/观测版本与待解决状态。明确状态机：prepared（持久准备成功）→committed（关联实际 Update）→unresolved/resolved；中断记录须可判定或保守展示。实施具体机制以 01 证明为准，不能仅列状态名就宣称崩溃一致。
6. 在同步 action 外预留收据预算并等待 prepared 持久成功，然后重核当前身份/epoch/可写状态/设计代次/目标源码及所有预算，再调用 03 同步提交。异步存储等待期间远端或授权变化使计划失效则拒绝/重新准备，旧记录显式中止，不产生历史。不得在 live action 内等待 IndexedDB。提交与本地 Update/收据落盘之间的崩溃按已验证协议恢复，无证据不得自动重放旧意图。
7. 收据与 Update 共用受控缓存总账，分别设置单项、累计、条数、pending 和缓存上限；同用户多标签页并发预留/压缩不能相互覆盖或突破预算。Quota/写失败停止相关结构写入并解释；未解决材料不能为腾空间静默淘汰。durable 仅确认权威文档，不清除 unresolved；正常刷新/重连/关闭保留并等待应保存任务。
8. 冲突面板提供原因、来源/目标定位、操作前片段和迟到修改材料；受影响范围暂停设计，保留安全范围和代码输入。人工恢复形成新的可信 PatchPlan，重验当前授权/epoch/原值/容量，不整份旧文档覆盖当前文件，不撤销他人贡献。显式完成/放弃按策略清理材料；本机清缓存/换设备的限制可见。
9. 授权撤销、账号切换、项目删除或 epoch 变化沿既有缓存规则清理对应材料，销毁历史、依赖元数据、监听与旧 doc 引用；临时认证/网络错误不能冒充确定撤权而清空材料。普通退出工作区可释放内存但保留未解决侧车。收据/检测保留窗口与“确认成功后何时可清理”沿 P0 决策，不能以 durable 作为晚到更新安全水位。

## 检查与交付物

交付会话历史工厂、依赖保护、侧车预算/状态协议、冲突观察和恢复入口契约；05～08 直接消费，不再各建历史或恢复机制。

- 两次插入→代码输入→undo/redo 顺序一致；无依赖时 HTML/link/CSS/vendor/许可/目录/顺序整体恢复，schema 有效，远端普通文本不被撤销。
- 乙编辑/引用甲新文件后，甲 undo/redo 整组拒绝且栈不丢；迟到贡献后冲突可检测，文本可查找，不宣传预检能看见未收到更新。
- 准备/提交/本地落盘各崩溃点、durable 后刷新、离线重开、跨标签页及 Quota 失败：材料可恢复或完整拒绝，不静默丢失。
- 恢复等待期间撤权/epoch 切换/删目标：旧计划不提交；确定撤权清理范围正确，其他项目/用户不受影响。

覆盖 FR-09/14/15、NFR-03/04、AC-11/12/13/14/20/21/23/25。若正式实现不再满足 01 证明，则重新关闭相关 P0 门禁，修复/重审后才能继续。

## 退出与后续

共享历史与全部冲突/存储失败 fixture 通过；恢复重新校验及确定撤权清理有证据，晚到文本可找回。将历史状态、写入门禁和恢复 API 交给[05](05-design-canvas-and-bridge.md)与 06；08 实现结构命令时重跑其真实操作。应用验证使用根 `.env` 和本机服务，禁止 Docker 与凭据输出。
