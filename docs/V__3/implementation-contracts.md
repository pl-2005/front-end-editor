# V3 写入、恢复和结构编辑约定

日期：2026-10-25。状态：方案已明确，代码待实施及验证。本文细化 R2/R5/R7 的实现边界，不改变 Y.Doc schema、后端协议或五步实施顺序。步骤 2 必须先验证这些约定，再开放按钮写入。

## 0. 运行检查到源码写入的门槛（2026-10-26 增补，待实施）

Step 01 已提供候选/歧义/未映射状态、实际检查文件和 mode revision，见[只读加固证据](evidence/step01-runtime-hardening.md)。本节其余按操作判断的写权限、运行差异展示及异步提交保护仍待 2C/3 实施。

当前检查运行页而非静态副本。来源关联不等于写权限；`nodeId`、CSS selector、DOM id/class、capability 和 WeakMap 命中均不能单独授予权限。命中动态节点时保持自身只读，不自动选最近可写祖先。

- 来源分为未映射、候选源码关联、歧义/失效。认领前 clone/replace/innerHTML 重建及重复标记必须有测试；不能证明唯一对应时不开放写入。候选定位只作提示，歧义时不提供确定源码定位。
- 文本写入只针对源码纯文本元素；当前可见文本/子节点结构与静态解析不符时禁用该操作。属性按欲编辑字段比较语义值，显示源码值与运行值差异；style 修改仍以原始声明为准，computedStyle 仅作反馈，外部级联差异本身不授予反写权限。
- inside/before/after/delete 分别判断：实际父子关系、相关子树或锚点顺序发生运行时改变、身份不明确或无法验证时禁用相关结构操作。显式 DOM 父级导航不改变源码的父级关系；不能把 JS 移动后的屏幕位置当成源码插入位置。
- 上述 DOM 观察只用于保守拒绝。用户 JS 与桥同环境，无法提供抗恶意脚本的静态身份认证；若产品要求这一保证，当前运行检查架构不能证明，应关闭该场景可视化写入。父层始终独立核验最新 Y.Text、代次、目标片段、合法候选及恢复预算，不由消息开放任意补丁。
- 源码区 activeId、项目 entryFileId、当前运行桥 fileId 分别保存。Bootstrap 准备、插入、属性和删除明确显示并绑定当前有效运行页 fileId；无有效运行目标时拒绝。运行 A/代码 B 时只能明确修改 A，导航到 B 后旧 A 意图取消。
- 源码/导航/项目/授权失效使草稿与命令失效；普通模式切换保留 iframe/通道，清理检查状态并使未提交草稿、落点和命令失效；已提交结果保留。异步提交前再次核验当前检查模式及 mode revision。提交等待期间运行态相关结构/字段变化也取消并重新选择，不根据旧屏幕几何重试。

新增门槛验证见验收表 2026-10-26 增补及[选择方案评审](selection-review.md)。当前只读检查不代表这些写能力已经实现。

## 1. 本机存储和预算

### 存储位置与计量范围

恢复材料固定放在现有 `web-editor:<userId>:<projectId>:<epoch>` 数据库的 `custom` store，使用 `visual:v1:` 键前缀；不新建侧车数据库或 object store，不改变 y-indexeddb 的 `updates` schema。沿用当前数据库关闭、撤权、用户退出、项目清理和 epoch 清理路径，并验证旧缓存升级兼容。本文的共享预算指同一 user/project/epoch 缓存，跨标签共享；不是整个浏览器、全部项目或物理磁盘配额。

定义以下逻辑字节数；所有本地日志及恢复写入都必须使用同一计量方法：

- `U`：`updates` 内实际持久化 Uint8Array 的 byteLength 总和；压缩后按新结果重新计算。
- `R`：全部 `visual:v1:` 材料、元数据及未结操作记录的编码字节数；文本按 UTF-8，元数据使用固定字段的 JSON UTF-8 编码，不把字符串 length 当字节。
- `Q`：已持久化、尚未被日志写入消费的容量预留；预留元数据本身计入 `R`。
- `P`：原有 pendingBytes，继续独立受 `OFFLINE_LIMIT = 1536 KiB` 约束。

每次新增材料或接受本地提交必须同时满足 `R <= 5 MiB`、`U + R + Q <= CACHE_LIMIT = 13.5 MiB` 和原 pending/update/document 预算。5 MiB 不是额外缓存空间；接近文档上限的项目可能没有足够恢复空间，界面须展示实际剩余额度。逻辑预算不承诺浏览器物理配额一定充足，真实 quota/transaction 失败仍须处理。

### 原子预留与跨标签竞争

1. 候选源码及日志增长上界在事务外生成。`OfflineLog` 提供统一的计量/预留入口；设计层不得独立读数后自行 put。现有 save、acknowledge、恢复追加和显式清理均接入该入口。
2. 在同一 `readwrite(['updates', 'custom'])` 事务内读取最新 U/R/Q/P，校验预算，分配缓存内单调序号，追加不可覆盖的 prepared 材料及 update 预留。依赖结果的后续请求在 IDB 回调内安排，不跨异步计算等待事务。只有 transaction complete 才算准备成功。
3. 两个标签的事务共享这两个 store；后提交者必须看见前者的记录与预留。同文件设计提交再以 custom 中的 fileId/owner/operationId/revision 条件记录实现排他提交，批量历史按排序后的 fileId 一次申请全部文件；不能只用进程内 Promise 队列。标签通知只用于刷新 UI，数据库条件检查才是依据。
4. live 提交前复核身份、缓存 revision、全部受影响源码、历史令牌及预留。落盘等待期间本标签阻止相关 Monaco/文件命令；其他标签即使继续源码编辑，也会使旧候选失效。两个标签并发设计只能有一个获得同文件提交资格；远端事务始终正常接收。
5. 关联 operationId 的日志写入在同一事务内写 update、消费 Q 并更新 R/P；acknowledge 压缩不得清除材料或尚未消费的预留。普通代码日志也必须计算 R/Q，不能绕过共享预算。
6. update 预留须覆盖实际编码增长，不能直接拿当前随机 clientId 的 scratch 长度作保证。预检副本先加载完整 live 状态，再在隔离副本中对齐本地 clientId/时钟及历史所需 redone 元数据，用相同确定性 action 和事务边界捕获候选 Update；副本不连接 provider 或本机日志。候选绑定文档 revision/clientId/历史令牌，提交前必须仍完全一致，按候选编码字节预留。任何路径不能复现同一编码，则先补足该路径的可验证增长上界，否则拒绝提交；不能等 live 写入后才发现容量不足。这是步骤 2 的可行性门槛，需验证插入/删除/多文件准备/历史、不同 clientId 与时钟编码边界，比较候选和实际编码字节。
7. 取消且确认没有提交的操作释放预留，保留恢复材料并记 canceled。崩溃后不能靠租约超时直接删除 prepared 或释放未知提交的预留；缓存加载、日志核对后才结算。未能证明时保守计入预算，允许用户查看材料并显式处理。失权时先使回调失效，再按现有路径清库，禁止迟到回调重建材料。

这些事务只保证本机预算和材料原子性，不把 IndexedDB 与内存 Y.Doc 伪装成同一事务。live 成功而日志或 committed 标记失败时，保留 prepared、提示实际提交状态并停止相关写入，不整页回滚。

远端更新不因本地恢复预算被拒绝或回滚。若无法同时保存新的合并正文和旧材料，保留旧材料，将检查状态标为“最新合并副本未保存”，当前文本从 live Y.Text 展示；禁止声称刷新仍能找回该份新副本。若更新日志也无法保存，沿用原 session 本地存储失败门禁，不能仍宣称离线可靠。

## 2. 恢复记录与容量满处理

before/after 是逻辑上可还原的正文，不要求每次物理保存两份整页快照。固定采用“不可变基线 + 可逆局部补丁 + 必要快照”的首版格式：

| 记录 | 必需内容 |
| --- | --- |
| 文件基线 | fileId、记录时路径、完整 HTML、内容摘要、格式版本；首次设计/Bootstrap 修改前保存 |
| 操作 | operationId、缓存序号、kind、来源标签、全部受影响 fileId、before/after 摘要、正向及逆向补丁、状态 |
| 保留内容 | 补丁中的原始 removed/replacement 文本；删除、属性替换及历史逆操作不能丢失将被移除的内容 |
| 检查状态 | 当前基线引用、最近本地意图引用、检查 revision、确认 revision、存储完整性状态 |
| 合并快照 | 远端变化或手写源码使补丁链无法衔接时，保存必要的新完整文本及版本；不覆盖旧操作依赖的快照 |

补丁偏移按 UTF-16，材料按 UTF-8 计量。普通设计补丁复用已验证的 expected/replacement；历史结果可用最长公共前后缀构造一个可逆替换区间，保留精确字符串，不要求节点语义 diff。相同全文/片段可按摘要索引复用，但复用前比较原文，引用关系和引用计数在同一事务更新。

新操作的 before 必须能从某个持久化基线/快照及有序补丁精确重建；若手写代码或远端变化使摘要断链，先存新快照再写 prepared。不能假定本地意图链等于当前合并文本。加载时验证格式、摘要、范围和依赖；断链只展示可确认的材料并暂停相关设计/历史，不猜测恢复正文。

prepared、committed、canceled 均保留可查看材料；prepared 不自动重放。仅在日志落盘完成且材料状态事务成功后标 committed，UI 分别展示源码已提交与本机保存状态。checkpoint 或去重不得移除未清理的操作前内容；durable、用户确认检查、后续意图都不触发清理。

容量满时显示占用、剩余空间、受影响文件和停止原因，提供复制材料、人工局部修复、确认检查、显式清理。清理前说明会失去哪些历史追溯材料；不自动淘汰、不以确认代替清理。清理以文件材料集合为单位，拒绝正在提交的文件，原子移除记录及引用，保留其他文件仍引用的内容。清理后在下一次设计写入前建立新基线。仅恢复材料不足时，正常代码编辑仍遵守原日志门禁；原日志满或失败时沿用 session 的更严格限制。

5 MiB 不承诺固定操作次数。必须测量：接近 200 KiB 页面连续 100 次小属性提交、本地插入后修改再删除、跨快照断链及大范围历史替换，记录实际 R 和可重建结果。超限场景必须在 live 写入前拒绝，并可取出已有材料；不以要求用户频繁清理掩盖每次整页复制的开销。

## 3. 共享历史接口和失效规则

以下是实施接口约定，名称可调整，不代表接口已经存在：

```ts
type HistoryCandidate = {
  direction: 'undo' | 'redo'
  token: { sessionGeneration: string; stackRevision: number; topItemId: string }
  files: { fileId: string; before: string; after: string; sourceRevision: number }[]
  updateBytesUpperBound: number
}
// previewHistory(): HistoryCandidate | undefined；不修改 live 文档或栈。
// commitHistory(candidate, preparation): 提交前复核，随后同步调用 live manager。
```

一个 session 持有一个正文 UndoManager，统一 scope/trackedOrigins/captureTimeout 配置，Monaco 卸载不销毁它。预检须复制预检会修改的栈项集合、元数据及 redone 信息；不得仅浅拷贝栈数组并假定隔离成功。每次 live 捕获、合并捕获、undo/redo、清栈及会影响候选的远端事务使令牌失效；来源/文件版本也独立核验。预检自身不能推进 live revision。

候选从整个 files scope 的前后差异得到全体受影响文件，不根据当前 activeId 猜测。纯代码历史且不涉及已有设计记录时保留原历史保护；涉及设计记录的文件必须先落盘可逆材料，并受需要检查/恢复失败门禁。同一栈项涉及多个文件时整体预检和提交，任一保护失败均零 live 写入、零栈消耗，不拆开撤销。普通 JS/CSS 历史不套用 HTML 200 KiB 或节点限制。

空栈不落盘；候选过期则取消而非重新套用旧补丁；live undo/redo 继续用 Yjs 历史语义执行，不用候选全文覆盖。需证明 preview 连续调用不改变 live 文本、栈项内容及 redone 状态，多轮 undo/redo 与远端插入下候选/live 结果一致。

BOOTSTRAP_ORIGIN 只排除准备动作本身；不能保证用户之后手写删除 link、删除 head 或撤销相关代码时引用永不失效。此类变化应使准备状态失效并提示重新准备，保留资源文件；不阻止合理代码历史，也不自动补回 link。

## 4. 首版结构插入矩阵

“普通容器”固定为 `body/div/main/section/article/aside/header/footer/nav`；必须有明确开始/结束标签、普通 HTML 命名空间及无歧义位置。该白名单内允许七模板内部追加，也允许以其直接子元素为锚点 before/after。其他元素可按能力查看、改属性或删除，但不因此获得内部插入能力。

| 目标或上下文 | 首版结构插入 |
| --- | --- |
| 上述白名单容器，祖先关系安全 | 七模板 inside；合法直接子元素的 before/after |
| p、h1–h6、span、a、button、label 等 | 不接受 inside；before/after 仅在其父级是白名单且上下文安全时允许 |
| head、html、void 内部、隐式/重排/缺标签节点 | 拒绝 |
| 列表、表格、select、template、SVG/MathML 及其受限子树 | 拒绝，保留源码编辑入口 |
| a/button 等交互元素内的嵌套容器或受限祖先 | 拒绝首版结构插入，不能借内部 div 绕过祖先限制 |

白名单只是第一道检查。提交前在完整候选源码上重新解析，验证插入区间映射到预期模板根节点、父元素和兄弟顺序，既有节点的范围随补丁平移后仍保持原父子关系；不能出现自动闭合、foster parenting、跨边界重排或新增相关解析错误。失败则零写入，不以重新序列化修复 HTML。模板卡片的静态子树也须整体通过。此规则从步骤 2 的按钮开始执行，步骤 3 仅扩展模板覆盖。
