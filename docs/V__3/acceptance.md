## 环境与数据

应用运行使用仓库根 `.env`，连接其中配置的本机 MySQL、MinIO、Redis；禁止 Docker / Docker Compose，禁止输出、记录或提交凭据。启动与构建沿用[V2 开发指南](../V__2/development.md)和[发布说明](../V__2/step11-release.md)，不得同时运行占用相同端口的完整启动器与既有验收脚本。

准备简单单文件、多 HTML + 共享/专用 CSS、Flex/Grid 嵌套页面、异常 HTML/执行入口四类 fixture。覆盖中文、emoji、实体、CRLF、注释、相同兄弟标签和重复 class/id；并发使用两个真实已授权会话，离线用已初始化且资源可用的设计画布。

## 测试层次与留存证据

- 核心单元测试：位置与编码、补丁不重叠/倒序、模板规则、父子合法性、同一 action 两次执行结果一致、失败无部分写入。测试用户可观察的源码结果，避免仅复刻实现。
- 前端集成测试：共享历史、可写门禁、投影不污染源码、消息过期/伪造/去重、取消与资源清理。
- 本机端到端验收：跨 iframe 指针与键盘、两个真实会话并发、离线重连、服务持久化重开、导出和复制。截图只证明外观，必须同时保存不含秘密的源文件断言、事务/状态结果与导出校验。
- 既有回归：前端 test/lint/类型检查/build；协作或后端被修改时运行相应模块检查。验证文件树、Monaco 语言服务、成员与同步/持久化状态、Sandpack 运行/控制台、授权、文件操作和已有导出行为。
- 性能记录：设备、浏览器版本、文件字节数/节点数、测试次数和最大/分位时延；默认验收指标见 NFR-05/06；实施前冻结测试配置，若调整必须同步记录决策和验收阈值。首次外部依赖加载与设计时延分开统计。

实现时新增实际脚本及 fixture 后再在实施记录中列出准确命令，不在本需求稿编造不存在的 V3 验收命令。测试结果注明提交/文件状态、环境、执行时间、证据位置和失败项；账号、凭据、私有备份留在受限本机。
