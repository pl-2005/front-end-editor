# V3 可视化网页编辑需求规格

日期：2026-10-10。状态：需求评审稿，待实施。需求来源为用户要求在当前项目基础上支持组件栏拖入页面并同步项目文件代码。

2026-10-12 用户确认：保留现有离线编辑，结构冲突采用提示与人工恢复；恢复材料在发起者本机持久保存，刷新后可恢复，团队/跨设备恢复留待后续。决策详见[技术评审 D-01/D-02](technical-review.md#用户已确认决策)，功能仍待实现及验收。

## 目标与数据归属

用户既可在 Monaco 编写 HTML/CSS/JS，也可在设计画布编辑静态 HTML 元素。两类操作修改同一份项目文件，并向团队成员同步、自动保存和导出。React 是编辑器界面的实现技术，组件栏提供依赖 Bootstrap 的原生 HTML 模板，不要求被编辑页面采用 React。

2026-10-12 用户要求引入 Bootstrap 作为组件栏依赖，纳入 FR-18。固定版本、项目内 CSS、基础静态模板、级联影响与验收补充见[Bootstrap 依赖方案](bootstrap-dependency.md)；此方案尚未实施。

“项目文件”默认指当前项目 Y.Doc 中按稳定 fileId 保存的文件；不指编辑器仓库自身的源码，也不自动写入用户电脑目录。实时写本地磁盘、Git 同步、npm 依赖管理属于后续独立需求。此默认解释须在产品说明中保持明确。

HTML 解析树、节点注册表、选中状态和画布几何信息为派生数据，不形成第二份权威页面。源码不得被画布 DOM 的 `innerHTML` 或全量格式化结果覆盖。

## 用户流程

1. 有效团队成员进入现有项目，选择一个 HTML 文件并切换设计模式；画布显示该文件及可解析的项目内 CSS。
2. 从组件栏选择组件，拖向画布；显示合法容器、插入线及前/后/内部位置。无法接收组件时解释原因。
3. 放下后修改对应 HTML，必要时同时创建或更新组件 CSS；Monaco、画布和协作者更新。
4. 点击元素定位源码，属性栏展示可编辑文本、属性及明确归属的样式；可以删除、移动或通过工具栏撤销。
5. 切换运行模式，在现有 Sandpack 中执行完整项目；设计模式的工具脚本和节点标记不进入运行源码或导出包。
6. 等待现有“已持久化”状态，离开再进入项目，验证源码与设计结果恢复；下载的项目文件与权威内容一致。

## 功能需求

| 编号  | 必须交付的行为                                                                                                                                                                                          |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-01 | 工作区增加组件栏、设计画布、属性栏和设计/运行模式切换；保留文件树、Monaco、在线成员及同步/持久化状态。                                                                                                  |
| FR-02 | 组件栏至少提供标题、段落、按钮、链接、图片、容器和卡片；模板包含默认 HTML、可编辑字段、允许的父子关系及必要 CSS。                                                                                       |
| FR-03 | 支持组件拖入空 body、容器内部、元素前后；每次拖入生成独立实例，HTML/CSS 一起提交，避免重复样式或 class 冲突。合法放下并完整校验后才写入；Esc、画布外放下或非法目标不修改 Y.Text、不产生撤销记录。       |
| FR-04 | 画布显示悬停和选中框，支持父层选择；点击可编辑元素打开对应文件并高亮准确源码区间。选中状态按当前解析结果更新或清除。                                                                                    |
| FR-05 | 支持纯文本节点的内容修改以及链接 href、图片 src/alt、按钮 type 等组件字段；嵌套标签中的文本明确选择编辑范围，不能用 textContent 覆盖整个子树。输入按文本或属性上下文编码。                              |
| FR-06 | 支持宽高、内外边距、颜色、背景、字号、边框，以及容器 Flex/Grid 基础布局。区分计算样式与可写声明，明确修改的是当前实例，不无提示改变共享 class 的其他元素。                                              |
| FR-07 | 支持兄弟排序及跨容器嵌套移动。禁止移入自身/后代、void 元素和非法 HTML 父子组合；表格、列表等特殊结构遵循可编辑规则。                                                                                    |
| FR-08 | 支持删除选中元素及其源码子树；复制现有元素时生成独立实例并处理重复 id。删除或移动不得误删相邻注释、兄弟节点或其他文件内容。                                                                             |
| FR-09 | 一次插入、删除、移动或属性提交是一个可撤销动作；无并发依赖时多文件整体撤销/重做。代码与画布共用本地操作顺序，不撤销远端贡献；新增文件已被远端修改或引用时保留文件并安全补偿，或拒绝整体撤销并说明原因。 |
| FR-10 | 手写代码后自动重新解析与刷新设计画布；临时语法错误不阻断代码输入，显示可编辑范围或暂停设计操作，修复后恢复。                                                                                            |
| FR-11 | 支持项目中多个 HTML 文件，设计目标与运行入口分别标识；切换设计文件不自动改变 entryFileId。正确解析相对 CSS 路径，引用不存在时提示。                                                                     |
| FR-12 | 设计模式限制用户 JS 执行，仅运行受控编辑交互；运行模式沿用隔离 Sandpack。JS 动态生成、无源码位置或已被运行时替换的节点不能冒充可编辑源码节点。                                                          |
| FR-13 | 所有可视化写入经过当前可写状态、身份、文件存在性和容量校验；与文本编辑共用 Yjs 同步及网关自动持久化，准确保留已同步/已持久化的区别。                                                                    |
| FR-14 | 支持现有有界离线编辑及重连。画布已初始化且资源可用时，离线可视化修改进入相同日志；重连复核权限和 epoch，超限、缓存失败或撤权时停止写入。                                                                |
| FR-15 | 过期画布命令、目标被删除或变更、文件切换及授权失效必须拒绝或重新验证，不能按旧偏移修改其他内容。多人结构冲突须可检测、可说明并保留可恢复文本。                                                          |
| FR-16 | 刷新/重新打开项目恢复可视化修改后的源码；现有导出包含最新 HTML/CSS，不包含画布节点标记、通信令牌、工具脚本或运行时补丁。                                                                                |
| FR-17 | 鼠标拖拽之外提供键盘/按钮式插入、移动、删除和撤销；组件栏、属性栏、选中状态具有可访问名称和合理焦点顺序。                                                                                               |
| FR-18 | 组件栏基础模板依赖固定版本 Bootstrap；按需原子引入项目内 CSS/许可及 HTML 引用，设计、运行、协作、持久化与 ZIP 样式一致。重复使用不重复引入，不覆盖用户资源；首次全页样式影响可见，实例编辑不误改共享规则；沿用容量、离线及历史保护。 |

## 样式与资源默认策略

Bootstrap 基础 CSS 与许可作为项目文件按需引入，设计/运行/导出使用同一依赖；实例 CSS 保留以下规则。首次引入可能影响同页旧元素，必须显示影响提示；不得把 Bootstrap 全局导入宿主工作区。

- 组件自带样式默认放入所编辑 HTML 所在目录的专用 `visual-components.css`；相对 link 按需插入，已有文件只增量补充。遇到同名用户文件无法确认归属时选择无冲突文件名，不覆盖原内容。
- 每实例使用无冲突 class；属性栏默认修改该实例的受控 CSS 声明。已有手写元素的简单样式默认修改其内联声明，并明确展示写入位置；复杂级联只展示计算结果及跳转源码，不猜测修改多个选择器。
- 尺寸、边距等值采用字段允许的单位与范围，保留未编辑声明。删除元素默认保留外部 CSS 规则，不盲目删除可能被其他元素或 JS 使用的样式。
- 图片支持 URL 或项目已有可用资源地址。当前文件协议不支持图片二进制文件，V3 不擅自复用私有 Y.Doc 存储桶为公共素材库；上传素材需独立权限、路径和存储设计，列为后续。

## 布局、兼容与非功能要求

| 编号   | 要求                                                                                                                                                                                                                                           |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| NFR-01 | 首版拖拽表示 DOM 顺序和容器归属；支持普通文档流及基础 Flex/Grid。不承诺拖到任意坐标自动得到绝对定位，CSS order/reverse/复杂 Grid 明确显示限制。                                                                                                |
| NFR-02 | 未触及区间的源码保持不变，包括注释、脚本、缩进、换行和属性引号；补丁引入的新内容采用邻近缩进风格。                                                                                                                                             |
| NFR-03 | 源码映射绑定 fileId、解析版本和画布会话，不能仅用 DOM 路径或字符偏移。相对位置必须结合最新源码语义校验。                                                                                                                                       |
| NFR-04 | 复用 100 文件、1 MiB/文件、10 MiB 总正文、12 MiB Y.Doc、2 MiB Update 和现有离线预算；不得为支持可视化绕过容量门禁。                                                                                                                            |

| NFR-06 | 拖动期间正文零写入，合法放下后一次提交；高频属性输入分组/防抖，避免每帧写入 Y.Doc。本评审默认验收基线为 200 KiB 内操作完成后画布在 1 秒内更新，不含首次外部依赖加载。实施前记录设备/规模并冻结指标；调整须同步决策与验收，未调整按本基线验收。 |
| NFR-07 | 桌面 Chrome/Edge、正常缩放与滚动为必测范围；窄窗口允许收起侧栏。触屏与手机完整拖拽列为后续，键盘替代操作必须交付。                                                                                                                             |
| NFR-08 | 画布通信验证窗口、可信 origin 策略、会话/渲染代次、消息结构及操作权限；不能传递认证凭据，不能通过任意消息写任意项目文件。                                                                                                                      |

## 明确边界与交付判定

V3 不新增历史版本、检查点、Git、任意 React/Vue 组件源码回写、自由坐标设计、动画编排、素材上传、协同选中框或服务端执行用户代码。现有 JS 保持源码原样，在运行模式执行；可视化行为生成静态 HTML/CSS，不自动生成业务逻辑。

多人编辑要求包含内容同步和冲突处理，不等同于承诺任意并发移动、删除与手写代码都能自动语义合并。发生无法证明安全的结构冲突时暂停受影响范围的设计编辑并提供源码定位及恢复内容；不得自动全量回滚，覆盖他人的合法更新。更强的结构串行化方案是否必要，由技术验证决定，不能用 Yjs 文本收敛证明结构正确。

按已确认的恢复范围，未解决的操作前片段和冲突证据在发起者本机按用户/项目/epoch 隔离并有界持久保存，普通刷新、重连或服务端持久化确认不能清除未解决材料；授权失效及 epoch 变化沿现有规则清理。浏览器缓存被清除或更换设备不保证恢复，产品须说明此边界。存储超限或写失败停止相关结构写入，不能静默丢弃恢复材料。用户选择人工恢复不降低冲突可检测、内容可找回和恢复操作重新校验的要求。

完整交付须覆盖 FR-01 至 FR-18、NFR-01 至 NFR-08 及[验收矩阵](acceptance.md)，所有失败路径可解释且不误写。阶段按钮 Demo 或单用户成功不能代替完整验收。默认策略及实施前技术门禁记录在[评审记录](review.md)。
