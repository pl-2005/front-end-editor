# Bootstrap 简单依赖方案

日期：2026-10-14。状态：待实施。沿用固定 Bootstrap 5.3.8，仅使用静态 HTML 和 CSS，不引入 Bootstrap JS/Popper。

## 准备动作

组件栏在当前 HTML 尚未引用可验证资源时显示“准备 Bootstrap”。提示首次引入可能改变已有页面样式；取消不改文件。准备完成才允许插入组件；准备可离线执行，但需构建内置资源已可用且现有会话允许写入。

构建中固定 npm 版本与 lockfile，从安装包读取官方 min.css 和 LICENSE；不请求 CDN。宿主 React/Ant Design 页面不导入 Bootstrap，缩略图及设计页隔离加载。

准备操作先查找内容与许可匹配的项目资源，存在则复用；没有则预生成唯一 fileId 和 `/vendor/bootstrap-5.3.8-<随机后缀>/bootstrap.min.css`、同目录 `LICENSE.txt`。使用现有虚拟目录协议，先准备完整创建计划，不在 scratch/live 执行时生成 ID。不同 HTML 使用按各自路径计算的相对 link，重复准备不插入重复引用，不覆盖同名用户文件。

CSS、许可、所需目录和当前 HTML head link 做完整预检后在一次事务内提交。容量/权限/路径/HTML head 任一失败，所有文件均不变化。不存在可安全插入的 head 时提示源码修复，不补全整页。并发首次准备允许唯一目录中出现两份依赖，各自引用正确，首版不自动去重或删除。

## 与旧方案的变化

准备和拖入组件分成两次独立动作，准备不进入正文 UndoManager。撤销组件只撤销组件 HTML，Bootstrap 文件和 link 留在项目里；用户界面明确说明。准备不触发正文捕获，前后切断历史分组，已有代码/设计历史不应因安装被清空。

此保证针对准备动作和随后的组件撤销；用户之后手写删除 link、删除 head 或撤销相关源码时，引用仍可能失效。此时使准备状态失效、提示重新准备，保留资源文件；不自动补 link，不承诺任意代码历史下 link 始终存在。准备写入同样遵守[实施约定](implementation-contracts.md)的恢复材料、联合预算和跨标签提交保护。

此取舍替代旧版“首次拖入所有资源和组件一起创建、一起撤销”的要求，避免撤销新文件隐藏他人贡献。恢复记录中仍须记录准备前后的 HTML，并对并发准备/引用变化保守提示检查。手工删除/重命名资源沿用文件树行为，引用失效则提示重新准备，不自动改其他页面。

## 模板与属性

七类模板为 h1/p/button/a/img/div/card 静态 HTML，按钮使用 btn/btn-primary，图片使用 img-fluid，卡片使用 card/card-body 等 class；初始图片地址由用户填写，不新增上传服务。

实例属性默认写内联 style，无专用 visual-components.css、随机实例 class 或共享 CSS 规则修改。按钮变体仅替换已识别的变体 token，保留其他 class。utility/`!important` 与内联值冲突时提示源码处理，不承诺覆盖所有 Bootstrap 样式。

CSS 和许可计入原文件、Y.Doc、Update 和离线预算；设计资源解析同样计量。删除最后一个组件也保留依赖。设计、运行、协作者、持久化、项目复制和 ZIP 均使用这些项目文件，不能只给设计投影暗加样式。
