# 前端重构实施记录

日期：2026-10-08。状态：已完成。

## 交付

- `frontend/src/V2App.tsx` 只装配 AppTheme、BrowserRouter 和 AppRoutes。`app/` 承担认证守卫、路由入口、公共壳和面包屑；保留公开/受保护 URL、资源 key、登录/注册 key 和每页公共壳的生命周期。
- 七个业务页面移入 `features/`。团队详情拆成头部、成员、审批、邀请、项目面板；数据由 `useTeamDetails` 统一维护，候选搜索由 `useInviteeSearch` 维护。列表、发现和收件邀请各有数据 Hook。
- 所有团队 reload 共用递增请求序号和 AbortController，包括初次加载和操作后的刷新。基础及所有者管理数据、错误写入前校验当前请求与身份；旧响应、旧失败和卸载后的完成不提交。身份切换隐藏旧快照，失去所有者身份清空审批和邀请。
- 项目详情及操作分别使用 `useProjectDetails`、`useProjectActions`；操作按钮和初始化重试组件复用。操作 Hook 接收页面唯一 busy/执行器，成功回调和刷新在同一次任务内 await，权限清理及一次错误提示沿用页面策略。团队保留 USER_NOT_FOUND 例外，API 的离线缓存清理封装未绕开。
- `MetadataFields`、`MetadataDialog` 复用名称/描述及草稿生命周期，表单 id 使用 useId。失败保留输入，未修改的编辑直接关闭，提交中禁用重复操作。创建团队由调用方保留原始字符串和空描述；项目创建由调用方 trim 并将空描述转 null。调用方已迁移，旧 ProjectEditDialog 已移除。
- 摘要更新合并到项目详情，保留 collaboration 与最新 stateVersion。工作区继续 lazy/Suspense，并保留 userId/projectId/epoch key。头部保留当前会话导出的 portal 挂载点，团队表格导出仍动态导入独立流程。
- 样式按原连续区域分组。除基础、认证、壳、团队、项目、工作区外，旧界面/共享布局、交互覆盖、控件覆盖及响应式规则单独保留，以保持原始级联顺序；不改变选择器、声明或设计。
- 同步更新 V2 架构、数据流、登录会话恢复方案的路由代码落点及文档索引。
